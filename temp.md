# Pacioli: Technical Summary

## Technical Summary

- `Pacioli` is a small, synchronous Python command-line study-session tracker.
- The application records study sessions in a local JSON file, then aggregates total study time by topic.
- There are no external dependencies, package metadata files, tests, or framework components; it uses only Python's standard library.

## Execution Flow

- Entry point: `pacioli.py:4`
- `main()` first calls `utils.fixEmptyFile()` to ensure `sessions.json` contains valid JSON if it is blank.
- It prints a welcome banner, then enters an infinite menu loop.
- The user selects a numbered action:
  - `Save a Session`
  - `Summarize History`
  - `Quit`
- Menu actions are stored as function references in `menu.mainMenuOptions`, allowing new options to be added centrally.

## Module Breakdown

### `pacioli.py`

- Application entry point and main event loop.
- Reads menu input, converts it to a zero-based menu index, resolves the corresponding option, and invokes its function.
- Handles non-numeric menu input with an `Invalid option` message.

### `menu.py`

- Owns presentation and menu dispatch.
- `welcome()` prints the application header.
- `mainMenu()` enumerates the keys of `mainMenuOptions`.
- `quitPacioli()` exits through `sys.exit("Goodbye!")`.
- Imports `useData` to connect menu entries to data operations.

### `useData.py`

- Implements persistence and analytics.
- `getSessionData()` prompts for a topic and duration, normalizes the topic to lowercase, and returns a record such as:

  ```json
  {"topic": "objects", "minutes": 120}
  ```

- `saveSession()` loads the complete JSON array, appends a new record, and rewrites the file.
- `summarize()` computes:

  ```json
  {
    "total_minutes": 120,
    "by_topic": {
      "objects": 120
    }
  }
  ```

### `utils.py`

- Provides startup data-file initialization.
- Reads `sessions.json`; if it is empty or whitespace-only, replaces it with `[]`.

### `config.py`

- Defines the single configuration value:

  ```python
  DATA_FILE = "sessions.json"
  ```

### `sessions.json`

- Acts as the entire database.
- Stores a top-level JSON list of session objects.
- The current sample data contains one 120-minute `objects` session.

## Data Model and Persistence

The storage model is intentionally simple:

```text
sessions.json
└── list[dict]
    ├── topic: str
    └── minutes: int
```

Every save operation performs a full read-modify-write cycle. There is no database, schema validation, locking, timestamp, user identity, or session deletion/editing functionality.

## Technical Characteristics

- Language: Python.
- I/O: terminal input/output plus local JSON file access.
- State: persisted only in `sessions.json`.
- Control flow: imperative loop with function-based menu dispatch.
- Analytics: one-pass aggregation over all stored records.
- Topic normalization: whitespace trimmed and converted to lowercase.
- Output: plain text menu prompts and pretty-printed JSON summaries.
- Configuration: hard-coded relative path, resolved from the process's current working directory rather than from the script's directory.

## Current Limitations

- Numeric but out-of-range menu selections raise `IndexError`; only non-numeric input is handled.
- Invalid minute input raises `ValueError` and terminates the program.
- Missing, malformed, or structurally invalid `sessions.json` is not handled.
- Negative or zero study durations are accepted.
- `saveSession()` rewrites the complete file, which is adequate for a single-user toy application but not safe for concurrent writers.
- `pacioli.py` calls `main()` at module import time, so importing it starts the interactive application.
- The function and variable naming style is inconsistent with common Python conventions (`mainMenu`, `jsonData` rather than `main_menu`, `json_data`).
- Generated bytecode under `__pycache__` appears in the working tree; it should generally be ignored by version control.

Conceptually, the program is a miniature ledger: each study session is an entry, while `summarize()` performs the bookkeeping pass that turns entries into totals. That makes the project structurally similar to a very small event log, though currently without the historical safeguards—timestamps, immutable identifiers, validation, and migrations—that make real ledgers trustworthy.
